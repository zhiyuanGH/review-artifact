# External input contract and provenance

No experimental data is bundled. The filenames below describe separately supplied inputs accepted by `scripts/regenerate.py --data-dir PATH`. These are derived snapshots of existing measurements, not new experiment requests. The rendering bodies and aggregation functions in `scripts/` define the complete field contract; loaders reject missing, incompatible or incomplete inputs rather than inventing data.

| Required input | Expected content and source analysis |
| --- | --- |
| `motivation_planning.json` | Exact derived `get_planning_run()` input for the full-builder 280-workflow cohort: `samples` with indices, domain/category, token counts and `qwen_wall_ms`; `sample_count`; `final_breakdown`; `manifest.prompt_builder`; `prompt_breakdown_summary` with original component attribution; `request_attempt_audit`; and source-relative path labels. The original loader reads `breakdown/per_sample_usage.csv`, `final_breakdown.json`, `planning_prompt_breakdown_summary.json`, `planning/manifest.json`, and the saved request ledger/log. |
| `motivation_codegen.json` | Exact `get_planning_codegen_run()` input for the 280-workflow cohort: retry-inclusive per-workflow `samples`, `sample_count`, `breakdown` with first-pass/final/retry cost counts, and source-relative path labels. The original loader reads `breakdown/codegen_breakdown.json`, `per_sample_codegen.csv`, `codegen_llm_benchmark.json`, and `codegen_llm_benchmark_first_pass.json`. Redrawing uses the derived samples and breakdown; raw generated code is not required for redraw. |
| `motivation_topology.json` | `rows`: exact `get_workflow_topology()` summaries for the full-builder population, including node/wave counts and reductions; `swimlane`: the exact workflow chosen by `get_swimlane_workflow()`, with its nodes, edges and parallel waves. The original source is the full-builder `planning/workflow.json`. This population is distinct from the call-chain static-audit inputs. |
| `generation.json` | Current generation-efficiency provenance: `workflow_count`, `per_workflow` rows (`workflow_index`, `workflow_id`, `domain`, `odabench_wall_ms`, `naive_wall_ms`, `odabench_tokens`, `naive_tokens`), planning/code-generation/interpreter aggregates, `odabench`, `naive`, `improvement` and source labels. Original planning and code-generation CSV/breakdowns and aggregate interpreter timing feed `build_metrics()`. Aggregate interpreter time is allocated equally across the workflows, not an independently measured per-workflow value. |
| `offloading_latency.json` | Current selected-ten offloading snapshot: `latency_records` with workflow/device/model identifiers, method, `latency_s`, completion/failure markers and sample counts; original `selection_policy`, `latency_summary` and `data_protocol`. Missing complete latencies remain null. `regenerate.py` passes the exact records to the current plotting function. |
| `offloading_resource.json` | Current schema-v2 R179 frozen resource snapshot. `load_frozen_timeline()` documents required `methods`, repeated `runs`, observed `samples`, shared time grid, `metrics`, `display_metrics`, statuses, placements, observed time ranges and interpolation-gap policy. Counter-interval CPU means are recomputed from the existing samples before drawing; unavailable GPU samples remain gaps. |
| `evaluation_sources.json` | Current audited active evaluation snapshot: `latency` consumed by `plot_execution_latency()`; `followup.timeline` consumed by `draw_timeline()`; `characterization` with hardware/model/framework per-workflow arrays, labels/orders and success/sample counts consumed by the three characterization renderers. `refresh_evaluation_sources.py` retains original raw-cohort fastest-successful selection and equal-weight aggregation functions for inspection. Full refresh requires the original manifests, validation/audit records, summaries and raw phone results, not just the derived snapshot. |
| `fidelity.json` | Separately supplied current construction-audit snapshot, including per-workflow static metrics, aggregate tool/order scores and ten-workflow `business_runs`. `audit_static.py` compares newly recomputed static metrics and the combined frozen business-state observations to this snapshot. Raw business-state executions are needed to independently re-audit those observed results. |

The external `--examples-dir` for `audit_static.py` must contain the original `selected_samples.json` (`samples` indexed by `selection_index`, with tau-bench reference actions) and `workflow.json` (`workflows` indexed by `metadata.selection_index`, with expanded nodes, parameters and edges). They must contain unique, matching IDs. The source's `expanded_audit()` applies the original ABI normalization and strict DAG-reachability rules. No sample population is included in this upload.

`figure_style.py` and the three adjacent JSON configuration files are included. They preserve the current colors, chart styles and series aliases. Added entrypoints route to explicit external input directories, keep help available before dependencies/data are loaded, and export JSON/CSV without manuscript macros. Unused historical ablation outputs, raw trace archives, LLM responses, model weights, provider billing records, physical device serials and author-machine paths are absent from the upload.
